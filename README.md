**Bring your own agent. Find a better way to work with it.**

You already have a coding agent. The next question is how you want to work with it: review changes in a desktop workspace, steer a session from your phone, or keep several projects moving from a terminal. Start with the agent you use and the task you want to make easier.

Interfaces that run, steer, review, or resume an existing coding-agent harness. General chat frontends and standalone agent frameworks belong elsewhere.

## How to choose

- Works with: Does it support your existing agent, login method, and operating system? A transcript viewer and a client that can start or steer work offer different capabilities.
- Runs where: Where does the interface run, and where does the agent execute? A local desktop app can still depend on cloud services.
- Needs access to: Which repositories, files, credentials, and remote connections must you give it?
- Keeps what: Can you resume sessions, inspect changes, and export history? What remains available if you switch clients?
- Human involvement: Can you approve actions and review results? Does background work continue when you close the interface?
- Main limitation: What would rule it out for your setup: agent support, platform support, remote access, or missing review controls?

Use these questions with the decision table. Every entry summarizes its linked documentation. These lists were not install-tested, so entries do not repeat that. A capability the linked page does not state is unknown.

## Desktop and project workspaces

- [AionUi](https://github.com/iOfficeAI/AionUi) - Desktop cowork app for macOS, Windows, and Linux that uses a built-in agent or attaches installed CLIs such as Claude Code, Codex, Gemini CLI, and OpenCode. It runs locally, with an optional web UI and chat-app gateways, and each agent executes on that machine with its own permission dialog. Team mode shares one folder. Unattended mode exists only when the selected agent exposes it. **Desktop app.**
- [CodeNomad](https://github.com/NeuralNomadsAI/CodeNomad) - Desktop and browser workspace aimed at OpenCode V2. Desktop builds bundle Node.js and connect to a shared OpenCode background service, so closing a window leaves that service and its sessions running; a password-protected server can be opened from a browser, with HTTPS on by default, Git has to be on the backend PATH for worktrees, and OpenCode V1 is not supported. **OpenCode client.**
- [CodexMonitor](https://github.com/Dimillian/CodexMonitor) - Tauri app that starts one Codex app-server per workspace, resumes threads, and shows approval prompts, diffs, and git state from that protocol. The desktop app is local-first on macOS, Linux, and Windows unless you enable a remote daemon. iOS support is in progress, and the daemon must stay running for a phone to connect. **Codex client.**
- [Nimbalyst](https://github.com/nimbalyst/nimbalyst) - Desktop workspace for macOS, Windows, and Linux running Codex and Claude Code, plus alpha OpenCode and GitHub Copilot and a Gemini provider. Each session uses its own git worktree, where you accept or reject rendered diffs. An iOS companion can answer, review diffs, and queue tasks while agents stay on the desktop. No isolation boundary exists beyond those worktrees. There is no separate export store. **Desktop app.**
- [opcode](https://github.com/winfunc/opcode) - Tauri desktop app for Windows, macOS, and Linux that browses and resumes Claude Code sessions under the Claude projects directory. It can run custom agents in separate processes, with file access set per agent. It talks to the Claude Code CLI, not other vendors' agents. Usage data can be exported, other app data stays on the machine, and separate processes are the only boundary described. **Claude Code client.**
- [OpenChamber](https://github.com/openchamber/openchamber) - Workspace for OpenCode sessions from desktop, a browser, VS Code, or iOS and Android. Desktop builds bundle a matching CLI; other surfaces use one already installed, and a session continues after you close the app. Pairing can use a private end-to-end encrypted relay, or a direct, LAN, tunnel, or SSH path. You review diffs in the UI. It is not affiliated with the OpenCode team. **OpenCode client.**
- [OpenWork](https://github.com/different-ai/openwork) - Desktop app for macOS, Windows, and Linux, built on OpenCode, for local files with your own keys or a local model. One MCP exposes those skills to Codex, Claude Code, or Cursor. Local use needs no OpenWork account. Cloud and the Den org control plane are optional. Paths outside ee/ are MIT, paths under ee/ are the OpenWork EE License, and earlier releases remain FSL-1.1-MIT. **Desktop app.**
- [Vibe Kanban](https://github.com/BloopAI/vibe-kanban) - Local web kanban via npx in a git repo, that runs Claude Code, Codex, Gemini CLI, Copilot, Cursor, and OpenCode. Each workspace has a branch, terminal, and dev server. You review the diff. The company is shutting down. The repo stays open source and community maintained, the current version can export, and remote services for issues, comments, projects, and organisations remain 30 days, then local-only. **Agent workbench.**
- [Orca](https://github.com/stablyai/orca) - Desktop app for macOS, Windows, and Linux, with iOS and Android companions, that runs Codex, Claude Code, OpenCode, and Pi. Each task gets its own git worktree and terminal on a machine you pick, including a remote host over SSH. You can send a diff comment back to the agent. The phone apps monitor and steer that session rather than hosting the agents. **Desktop app.**
- [T3 Code](https://github.com/pingdotgg/t3code) - Electron, local web, and iOS and Android clients for harnesses on your computer: Codex, Claude Code, Cursor, Grok Build, OpenCode, and Antigravity. The t3 server there starts the agents and can keep running as a background service, with permission modes and remote access. Transcript storage and export are not described. It is early. Expect bugs. Antigravity is a setting rather than a separate CLI. **Desktop and mobile client.**
- [Paseo](https://github.com/getpaseo/paseo) - Desktop, mobile, web, and CLI clients attach to a daemon on your machine that launches Claude Code, Codex, Copilot, OpenCode, and Pi. You can start at the desk and open the same agents from a phone. Pairing can use an end-to-end encrypted relay, or direct TCP or Tailscale if you decline it. Plugins run on the daemon host. There is no telemetry or forced login. **Desktop and mobile client.**
- [Superset](https://github.com/superset-sh/superset) - Desktop workspace that runs Claude Code, Codex, OpenCode, Cursor Agent, or another CLI in a git worktree. macOS is the primary install, the Linux AppImage is experimental, and Windows is not available. Worktrees separate files but do not sandbox processes. It has terminals and diff review. An iPhone app can steer a connected computer only with Superset Pro, iOS 26 or later, and Remote Access. **Desktop app.**
- [Emdash](https://github.com/generalaction/emdash) - Desktop app for macOS, Windows, and Linux that runs installed CLIs such as Claude Code, Codex, OpenCode, and Amp, each task in its own git worktree. State stays in a local SQLite database, and SSH credentials stay in the OS keychain. It does not send code or chats to Emdash servers, though each CLI still talks to its provider. Hooks apply to Emdash sessions only. **Desktop app.**
- [Codeg](https://github.com/xintaofei/codeg) - Workspace that imports and resumes Claude Code, Codex, OpenCode, and Gemini sessions and can pass part of a turn to another agent with @. It runs as a desktop app, headless server, or Docker. iOS and Android clients only connect to that host. Files, CLIs, and conversations stay on that machine. Unattended to-dos get a worktree and wait in review until you accept them. **Multi-agent workspace.**
- [Jean](https://github.com/coollabsio/jean) - Tauri desktop app that drives installed CLIs, including Claude Code, Codex, Cursor, OpenCode, Pi, and Grok, across local projects and git worktrees. Sessions use Plan, Build, or Yolo modes, with a plan-approval step. An optional token-protected HTTP server can serve that UI to a browser on your network. macOS is tested, Windows is not fully tested, and Linux is community tested. **Desktop app.**
- [Helmor](https://github.com/dohooo/helmor) - Local workbench that runs Claude Code, Codex, Cursor, OpenCode, and Kimi in parallel, each task in a git worktree under ~/helmor/ on your machine. Downloads list macOS and Windows, and the CLIs are bundled. The window shows diffs and pull requests. A CLI and MCP server share one local database. An experimental phone path tunnels to the desktop, and no Linux build is listed. **Desktop app.**
- [Proliferate](https://github.com/proliferate-ai/proliferate) - macOS app that runs Claude Code, Codex, OpenCode, Cursor, and Grok through each tool's native harness. Each task gets an isolated git worktree for its branch, terminal, conversation, and review state. The control plane can be Docker or cloud, and the desktop can point at it. Which machine executes the agent once that control plane is remote is not stated. **Desktop IDE.**
- [Sculptor](https://github.com/imbue-ai/sculptor) - Experimental desktop research preview for agents in parallel workspaces. Each workspace is an isolated copy of your code, as isolated worktrees of the repo. Integrated choices are the Pi harness and Claude Code, and any terminal-based agent can be started from the app. You can review, then open a GitHub pull request. Downloads list Mac Apple Silicon and Linux. Container or remote execution is experimental. **Desktop app.**
- [Supacode](https://github.com/supabitapp/supacode) - Native macOS app that puts each coding-agent task in its own git worktree and a terminal kept by a background session daemon, so quitting the app does not drop scrollback. A beta SSH mode manages a remote repository over one multiplexed connection when that host runs the same daemon, and hooks the app installs flag Claude, Codex, and Copilot panes as busy, waiting, or idle. **macOS app.**

## Mobile and remote access

- [CloudCLI](https://github.com/siteboon/claudecodeui) - Web interface for Claude Code, Cursor CLI, and Codex, opened in a desktop or mobile browser while agents run on the host machine. The self-hosted app discovers local sessions and uses Claude Code's own settings, with tools disabled until you enable them. An experimental sandbox and a separate hosted service are described. The local server needs no account. **Web client.**
- [Happy](https://github.com/slopus/happy) - Mobile and web client, plus a separate macOS desktop download, for Claude Code and Codex sessions started by a wrapper on your computer. Running happy claude or happy codex launches the agent. The phone restarts that session in remote mode and does not host the agent. Sync is end-to-end encrypted, and notifications arrive for permission or errors. The computer has to stay available. **Mobile and web client.**
- [Kanna](https://github.com/jakemor/kanna) - Local web UI on a Bun server that runs Claude Code, Codex, Cursor, or Grok as child processes and ships a Pi agent in-process. Chats group by project, sessions can resume, and plan mode asks you to approve a plan before execution. History is JSONL in a local directory. Other machines can connect if you bind a host. No native phone app is described. **Web client.**
- [OpenCode Mobile](https://github.com/dzianisv/opencode-mobile) - Android client for an OpenCode server you run yourself over LAN, Tailscale, a Cloudflare Tunnel, or ngrok. It speaks OpenCode's HTTP and event stream, so model calls and files stay on that server. You can approve tool calls, and credentials sit in the Android Keystore. There is an offline demo and no iOS build. The app is not made or endorsed by the OpenCode project. **Android client.**
- [Sillage](https://github.com/MarlBurroW/sillage) - Self-hosted, mobile-first web UI that drives the native Claude Code and Codex CLIs on your own machine. The browser or installable PWA steers a session while the CLI runs on that computer, which has to stay available. Sessions outlive the client, with full-text search across conversations, an IDE panel, and a board agents read through its own MCP server. **Mobile and web client.**
- [VibeTunnel](https://github.com/amantus-ai/vibetunnel) - Terminal proxy that puts shells in a browser so you can run or watch commands, including Claude Code, from another device. The menu-bar app is Apple Silicon Mac only. The npm server covers Linux and Intel Macs on recent Node, and Windows is not supported. Access is direct HTTP or Tailscale. Approval prompts stay in the proxied terminal, not a separate review UI. **Terminal proxy.**

## Terminal and session navigation

- [Agent Sessions](https://github.com/jazzyalex/agent-sessions) - macOS app that searches local transcripts from Codex, Claude Code, Cursor, OpenCode, and other coding-agent formats, then resumes supported sessions by copying a command or opening the CLI in Terminal, iTerm2, or Warp. The search index stays on the Mac, and session history is not uploaded. OpenClaw is browse-only, with no resume. It reads logs rather than starting new work. **Session browser.**
- [Claude Squad](https://github.com/smtg-ai/claude-squad) - Terminal app that runs Claude Code, Codex, Gemini, Aider, OpenCode, Amp, and other local programs in separate tmux sessions and git worktrees. You watch them from one window, switch between a preview and a diff, and can check changes out before pushing. An experimental flag auto-accepts prompts for Claude Code and Aider. It needs tmux and the GitHub CLI. Config lives in its home directory. **Terminal app.**
- [herdr](https://github.com/herdrdev/herdr) - Terminal program that keeps panes for CLIs you already run, including Claude Code, Codex, Cursor, OpenCode, and Grok, inside a background server. It does not wrap or replace those agents. It owns their terminals and marks each pane working, blocked, or idle. A saved layout can return after a restart, but the original processes do not survive. Local and SSH machines share one window. **Terminal runtime.**
- [Toad](https://github.com/batrachianai/toad) - Terminal UI for Linux and macOS. Native Windows support is lacking, though WSL is noted. It launches Claude, Gemini, and Codex through the Agent Client Protocol. A shell keeps its directory and environment between prompts, several agents can run at once, and earlier sessions can resume. Toad is licensed under AGPL-3.0, the GNU Affero General Public License version 3. **Terminal UI.**
- [dmux](https://github.com/standardagents/dmux) - Terminal multiplexer that creates a tmux pane, git worktree, and branch per task and can start Claude Code, Codex, OpenCode, Gemini CLI, Cursor CLI, and others. The pane menu can merge the branch or open a GitHub pull request. Recreating a pane can resume a tracked Codex or Claude conversation. Optional inference login names and summarizes without replacing the agent CLI. **Terminal multiplexer.**
- [Agent Deck](https://github.com/asheshgoplani/agent-deck) - Terminal session manager for macOS, Linux, and Windows through WSL that lists Claude, Gemini, OpenCode, Codex, and other coding-agent sessions in one text UI. You can fork a supported session, send a prompt, attach MCP servers, or open a web UI on localhost, and a conductor flow can watch Claude sessions from Telegram; sandboxed sessions get a container shell. **Terminal app.**
- [Pane](https://github.com/greenfield-inc/Pane) - Terminal-first manager for macOS, Windows, and Linux that runs an existing CLI, including Claude Code, Codex, Cursor Agent, Aider, or Goose, instead of replacing it. A new session creates a git worktree, and removing the session cleans it up. Status marks show when an agent is waiting for approval. Remote Pane is self-hosted, so the host keeps the repos, credentials, and processes. **Terminal manager.**
- [Parallel Code](https://github.com/johannesjo/parallel-code) - Electron app for macOS and Linux that starts Claude Code, Codex, Gemini CLI, Copilot CLI, or Antigravity, each task on its own git branch and worktree. You review diffs, comment inline, and merge from the sidebar. A phone can watch over Wi-Fi or Tailscale after a QR scan. Optional Docker isolation does not cover Antigravity, because that CLI's keyring login cannot run inside the container. **Electron app.**
- [cmux](https://github.com/manaflow-ai/cmux) - Native macOS terminal, using libghostty, whose sidebar lights up when a coding agent notifies it or a hook says it is waiting. Resume hooks for Claude Code, Codex, OpenCode, and other listed CLIs can store a session id and rerun it, and you can turn that off. It is a terminal you drive yourself, not a worktree manager or an approval policy. **macOS terminal.**
- [Agent of Empires](https://github.com/agent-of-empires/agent-of-empires) - Session manager for Linux and macOS, with a text UI, browser dashboard, CLI, and HTTP API. Each agent runs in its own tmux session and keeps going after you detach. It covers Claude Code, OpenCode, Codex, Gemini CLI, Copilot CLI, and other terminal agents. Git worktrees, plus optional Docker, Podman, or Apple containers, separate the work. A diff view is included. **Terminal session manager.**

## Editor integrations

- [CC GUI](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui) - JetBrains plugin that opens chat and diffs for installed CLIs, mainly Claude Code and Codex, with Grok, Kimi, and OpenCode marked beta. You accept or reject edits in the IDE, with permission controls and message export. The plugin starts those CLIs rather than calling a model API, so sign-in stays with the agent. It does not run the agent on another machine. **JetBrains plugin.**
- [Obsidian Agent Client](https://github.com/RAIT-09/obsidian-agent-client) - Obsidian plugin that starts installed Agent Client Protocol agents, including Claude Code, Codex, and Gemini CLI, as child processes that can read and edit vault notes. Each action asks permission unless you turn on auto-allow. Sessions can resume when the agent supports it, and chats can be written as Markdown. It is desktop-only. Agents keep terminal access, and API keys sit in Obsidian's keychain. **Obsidian plugin.**
- [agent-shell](https://github.com/xenodium/agent-shell) - Emacs package that opens a buffer on Agent Client Protocol agents you install yourself, including Claude Code, Codex, Gemini CLI, Goose, Cursor, and OpenCode. The editor is only the interface. The agent process is still that CLI, reached through the companion package acp.el. Optional add-ons cover notifications and review. No sandbox around the agent is documented. **Emacs package.**
- [claudecode.nvim](https://github.com/coder/claudecode.nvim) - Neovim plugin that starts the Claude Code CLI in a split terminal. It creates a WebSocket server on a random port, and the CLI connects to that server. Proposed edits open as Neovim diffs you accept or reject. It needs Neovim 0.8 or newer, the Claude Code CLI, and snacks.nvim. The plugin is marked beta. **Neovim plugin.**

## Team and multi-agent control planes

- [Mission Control](https://github.com/builderz-labs/mission-control) - Self-hosted web app for tasks and runs from OpenClaw, Claude Code, and Codex, plus CrewAI, LangGraph, and AutoGen with uneven adapter coverage. The dashboard runs on your machine against SQLite. You create the first admin and an API key. It is alpha, so read its guidance before exposing the port. It records approvals and spend but does not replace the agent's tool loop. **Web control plane.**
- [Gas Town](https://github.com/gastownhall/gastown) - Workspace manager that runs Claude Code by default, or Copilot, Codex, Gemini, or Cursor. Work lives in git-backed hooks, not only agent memory. The Mayor oversees workers in git worktrees, and a merge queue handles finished branches. Install Git, tmux, and the agent CLI, or use the Docker sandbox. No graphical approval inbox apart from the CLIs. **Workspace manager.**
- [Multica](https://github.com/multica-ai/multica) - Source-available workspace where CLIs such as Claude Code, Codex, Cursor, Copilot, and OpenCode are assignees on a computer you connect. The agent comments on the issue, and the result waits for review rather than merging itself. Live steering is documented for Claude Code, Codex, and Grok. Self-hosting uses Docker Compose or Helm. A daily anonymous snapshot of version and bucketed counts is sent unless DO_NOT_TRACK=1. **Team workspace.**
- [BOSS](https://github.com/risa-labs-inc/BossConsole) - Desktop console for macOS, Windows, and Linux that runs Claude Code, Codex, Gemini CLI, or OpenCode in its terminal. A loopback MCP server exposes the embedded browser, editor, git tools, and secrets. Role checks and a per-tool kill switch decide which tools an agent may call. A QR flow can share the terminal with a phone while execution stays on your machine. **Desktop console.**
- [Cline Kanban](https://github.com/cline/kanban) - Local web preview, started with npx kanban in a git repo, that gives every card its own terminal and git worktree and launches the CLI it finds installed. This research preview can bypass permissions, and linked cards with auto-commit can start the next task alone. You can instead watch the card, comment, commit, or open a pull request yourself. **Local web app.**
- [Agent Orchestrator](https://github.com/Untrivial-ai/agent-orchestrator) - Local desktop app for macOS, Windows, and Linux that supervises harnesses you already use, with one worker, one branch, and one git worktree per task. A project orchestrator can split a plan into those workers. The kanban comes from session, pull request, CI, and review state, including work that needs a person. A bundled daemon watches the agents. Chat or the agent terminal is available. **Desktop control plane.**
- [AI Maestro](https://github.com/23blocks-OS/ai-maestro) - Local dashboard for terminal agents such as Claude Code, Codex, and Aider. The UI sits on your machine. Agents run in tmux or in optional Docker, EC2, or ECS placements, and other computers join a peer mesh with no central server. Agents can message each other while you are away. A memory skill stores notes redacted of secrets. Windows is documented through WSL2. **Local control plane.**

## Contributing

Missing something useful? Read the [contribution guide](CONTRIBUTING.md) and open an issue or pull request with an official source.

The machine-readable [list.json](list.json) includes a primary-source link and a documentation-check date for every entry. Descriptions are short editorial summaries of that linked documentation. Inclusion does not mean the project was installed, run, security-tested, or endorsed. Hosted services and source code may have different terms.

To update the list, edit `list.json`, run `bun run build`, then `bun run check`. The README is generated; avoid editing it directly.
